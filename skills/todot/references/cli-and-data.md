# todot CLI、字段与路径参考

依据本项目 `src/cmd/`、`src/cli.rs`、`src/todo.rs`、`src/note.rs`、`src/xdg.rs` 和 `src/core/` 的实现。执行前核对本机帮助。所有写命令和直接文件修改都受 `SKILL.md` 的二次确认规则约束。

## 1. 数据位置与 theme path

先读取有关环境变量，解析绝对路径；不打印全部环境。下表中的数据根目录记为 D，配置根目录记为 C。

| 位置 | 解析规则 |
|---|---|
| D | 设置了 `TODO_DIR` 时使用其值，否则 `$HOME/.todot` |
| 当前待办 | CLI 子命令：`TODO_FILE` → `D/todo.txt`；TUI 另支持显式 `FILE`，其优先级最高 |
| 归档 | `DONE_FILE` → 当前待办文件旁的 `done.txt` |
| C | 非空且为绝对路径的 `XDG_CONFIG_HOME` → `D/config`；相对 XDG 值被忽略 |
| 界面配置 | `C/todot/config.toml` |
| 快捷键配置 | `C/todot/keybinds.toml` |
| theme path | 自定义主题目录 `C/todot/themes/`，加载其中的 `*.toml`；内置主题不一定有磁盘文件 |
| 正文根目录 | 非空 `NOTES_DIR` → 配置的非空 `notes_dir` → `D/notes`；配置中的 `~`／`~/` 会展开 |
| 手机录入暂存 | 当前待办文件旁的 `inbox.txt`，TUI 合并；CLI `list` 不主动合并它 |

`TODO_FILE` 不会自动改变 D，也不会让正文／配置改到该文件旁边；自定义文件时尤其注意这点。相对路径依当前工作目录解释；环境变量路径应预先展开为绝对路径，shell 引号内的 `~` 不自动展开。

示例（仅在目标文件已经存在时查询）：

```bash
TODO_FILE='/home/user/work/todo.txt' DONE_FILE='/home/user/work/done.txt' NOTES_DIR='/home/user/work/notes' todot --json list
```

后续操作保持相同环境与工作目录。不要用 `todot /path/to/todo.txt list`：显式文件是 TUI 接口，不是子命令选文件接口。

**theme 是界面配色，不是任务分类。** 当前任务 JSON 没有 `theme`、`theme_path`、`path` 或 `body` 字段。向用户展示 theme path 时说明它是配置目录；任务正文路径来自 `raw` 中的 `note:`。不要把主题当作项目。

主题设置是简化的 `key = value` 文件（虽名为 `.toml`，不应假定完整 TOML 语法）：

```text
theme = Muted Slate
theme_mode = auto
theme_dark = Nord
theme_light = Dawn
```

`fixed` 用 `theme`，`auto` 按终端深浅模式选 `theme_dark`／`theme_light`。改配色先读现有配置，预览精确键值变更并二次确认，保留其他键；没有 `todot theme` 或 `todot config` 子命令。

## 2. 任务数据含义

一条任务是一行 todo.txt 文本，例如：

```text
(A) 2026-11-18 整理发布说明 +工作 +发布 @电脑 due:2026-12-01 t:-3d rec:+1m note:tasks/example.md
```

`todot --json list` 返回任务数组，任务字段如下：

| JSON 字段 | 含义与注意事项 |
|---|---|
| `n` | 从 1 开始的当前任务编号；可用于写命令，不是永久 ID。列表排序／筛选不会改变该编号；删除、归档、重复任务插入会使编号移动。若文件有空行，按解析后的非空任务顺序编号，不自行按物理行数推算 |
| `raw` | 完整任务行，含标题及所有元数据；修改时以此为基准保留未涉及内容。不是多行正文 |
| `done` | 布尔完成状态；`x ` 前缀表示完成，与归档位置是两件事 |
| `priority` | `A`–`Z` 或 `null`；A 排最前，Z 最后，未设置再后。不自创 P0／P1 映射，也不擅自认定 B 对应某种紧急程度 |
| `created` | 创建日期字符串或 `null`；`add` 通常自动补本地当天。任务开头的日期不是截止日期 |
| `completed` | 完成日期或 `null`；完成任务的日期顺序是 `x 完成日期 创建日期 标题` |
| `projects` | 去掉 `+` 的项目名数组；一条任务可有多个项目。是逻辑标签，不是文件夹或仓库路径 |
| `contexts` | 去掉 `@` 的场景名数组；如电脑、电话、家里，也可表达对象或执行环境 |
| `due` | `due:` 后的原始值或 `null`。表示截止日期，不是自动过期删除时间，也没有小时、时区、提醒时间。agent 必须验证为真实 `YYYY-MM-DD` 后才算逾期 |
| `rec` | 重复规则原始值或 `null`；完成时生成下一期，不是定时创建或推送 |
| `t` | 开始显示／延后显示的 threshold 原始值或 `null`；不是截止日期，也不禁止提前完成 |

其他信息从 `raw` 中获取，不要假装 JSON 已提供：

- 标题：去掉完成前缀、日期、优先级和元数据的可读描述；展示时可隐藏内部 `note:` 链接，但保存时保持原文。
- `note:tasks/example.md`：外部多行正文／笔记链接，相对正文根目录解析；绝对路径直接指文件。内置正文编辑器常生成 `tasks/<随机标识>.md`，外部笔记入口可能使用 `projects/todot-tasks/<标题slug>.md`。没有链接时不能仅凭同名文件猜正文。
- `note:"简短说明"`：旧格式行内说明，不是文件路径；不要把引号内部的 `note:` 文字当作文件链接。取引号外首个非空、无引号的 `note:` token 作为正文链接。
- `id:...`、`clickup:...`、`clickup_status:...`、URL 或其他 `key:value`：扩展元数据。保留但不虚构含义，`id:` 也不保证本应用提供唯一性约束。
- 正文保持 Markdown、多行、缩进、代码和原始字节；正文中的 `+`、`@`、`due:` 不自动变成任务字段。CLI 不返回正文内容，也不搜索链接文件里的内容。

### 日期、重复与延后显示

- 提醒以用户时区和日期为准；CLI 生成的创建／完成日期使用进程本地日期。两者不一致时先说明并解决，不能把 UTC 日期硬当用户今天。
- 截止当天未完成是“今天到期”；下一天才是逾期。没有截止日期不算逾期，已完成任务不提醒为逾期。
- `rec:Nd/Nw/Nm/Ny/Nb`：正整数周期，单位分别为天、周、月、年、工作日。`b` 只排除周六周日，不考虑节假日。
- 普通 `rec:1w` 从完成当天加一周；严格 `rec:+1w` 从原截止日期加一周，没有有效原截止日期时回退为完成当天。严格规则的下一期可能仍逾期，不擅自跳过多期。
- 月／年运算会截到合法月末；`rec:0d` 或未知格式无效。完成时移除当前优先级、补日期，生成的下一期保留原任务相关元数据；用重新查询确认正文链接和新编号。
- `t:YYYY-MM-DD`：在该日期及之后显示。`t:[+-]?N[d|w|m|b]` 支持相对偏移，先以有效 `due` 为锚，否则以 `created` 为锚；`t:-3d` 为提前三天显示，`t:0d` 为锚日期当天。无锚或格式无效不隐藏；不支持 `y`。若 `due` 存在但无效，相对计算失败，不凭空推断日期。
- 重复／延后标签和值可能无效，CLI 解析较宽松；agent 写入前校验，读取异常时提示而非静默“修正”。重复 `due:`／`rec:`／`t:` 只取首个，不能追加新日期指望覆盖旧日期。

## 3. 查询命令

以下命令只在已存在的待办文件上作为只读操作使用；缺失文件会被 CLI 自动创建。

```bash
todot --json list                       # 当前文件全部任务，含完成、未来任务
todot --json list '+工作' '@电脑'         # 项目与场景交集
todot --json list '发布'                 # 标题行内不区分大小写的子序列模糊匹配
todot --json list 'due:2026-12-01'       # 截止日期恰为该天
todot --json list 'due:+1w'              # 今天至一周后，含两端
todot --json list 'due:-3d'              # 三天前至今天，含两端，不是“所有逾期”
todot --json listpri                    # 所有有优先级的任务
todot --json listpri A                  # 只取 A，不是 A 及以上范围
todot --json listproj                   # 当前文件的项目名，包括完成任务
todot --json listcon                    # 当前文件的场景名，包括完成任务
todot --json listall                    # 当前待办和归档分开返回
```

项目／场景按完整名字精确匹配、区分大小写；每次最多一个项目和一个场景条件。同类多个条件只有最后一个生效，需要多项目交并集时读取 JSON 后自行筛选。普通搜索是子序列模糊匹配，不适合据此直接删除；写操作必须核对完整目标。

`due:+1w` 之类是**查询范围语法**，任务里存的截止日期仍须是绝对日期。范围支持 `d/w/m/b`，不支持 `y`；只解析首个合法的 `due:` 查询词。无效词会退回普通文本搜索。找全部逾期任务应读取所有任务，再验证并比较日期，不能只用 `due:-3d`。

JSON 形状：

- `list`／`listpri`：`[{"n":1,"raw":"...","done":false,...}]`，空结果是 `[]`。
- `listall`：`{"ok":true,"action":"listall","todo":[...],"done":[...]}`；两数组编号各自从 1 开始。**写命令默认只操作当前待办，不能把归档中的 n 直接传进去。**
- `listproj`／`listcon`：`{"ok":true,"action":"listproj","tags":["工作"]}`，标签不含 `+`／`@`。
- 文本列表默认按完整任务行不区分大小写排序，不等同于截止日期排序。不要把返回数组的第 3 项理解为任务 #3。

## 4. 写命令：只在预览后获得二次确认才执行

下面编号与日期均为示例，每条命令是独立范例，不是可批量执行的教程。执行前必须从用户数据选出真实目标、完整预览并等待确认。

```bash
todot --json add '(A) 整理发布说明 +工作 @电脑 due:2026-12-01'
todot --json append 3 '+发布'            # 尾部追加标题文字／标签，不是写多行正文
todot --json prepend 3 '尽快'            # 在标题前添加，保留前缀日期和优先级
todot --json pri 3 A                    # 设置优先级
todot --json depri 3                    # 移除优先级，也支持多个编号
todot --json replace 3 '(A) 2026-11-18 整理发布说明 +工作 @电脑 due:2026-12-03 note:tasks/example.md'
todot --json del 3 '+发布'               # 仅移除完整空白分隔 token
todot --json done 3                     # 标记完成，重复任务可能插入下一期
todot --json done 3 5                   # 支持批量；必须预览全部目标
todot --json archive                    # 移走全部已完成任务，不支持按编号归档
```

- `replace` 替换**整行**，不是部分字段 patch；不要丢失创建日期、正文链接或不相关标签。新增不要传换行符制造多条任务；多行内容使用正文文件。
- 改 `due`／`t`／`rec`：从最新原文替换或移除对应 token，并预览完整结果；没有专用 date 或 recurrence 子命令。
- `del N TERM` 只移除完整 token，不是任意子串；如果 TERM 是纯数字，会被解释成额外任务编号，改用完整 `replace` 避免误删。用 `del N note:...` 仅移除链接，并不等于安全删除正文文件。
- 整条任务删除：`todot --json del 3` 会另弹 CLI stdin 确认。agent 不能自己回答提示来冒充用户二次确认。**只有用户已完成会话层二次确认并核对目标未变时**，可运行 `todot --json --force del 3`，跳过重复的 CLI 提示。`--force` 本身从不是授权；不可用于未确认操作。可传多个已确认编号，CLI 按降序删除。
- 删除可能清理正文根目录内已无其他待办／归档引用的关联文件；即使是已完成任务也要核对引用。根目录外文件不由 CLI 自动删除。完成和归档通常保留正文，不是删除。
- `done` 不能反向恢复已完成任务；恢复可让用户用 TUI，或将移除 `x` 与完成日期后的完整行作为 `replace` 方案再次确认。已丢失的旧优先级无法自动找回。
- 没有归档恢复／归档删除、正文 CRUD、配置编辑或持久撤销的 CLI 子命令。归档操作优先交给用户 TUI，不擅自直接改写 `done.txt`。`update` 提示从仓库重新构建，不是任务更新；修改任务用 `replace`。

### 写入结果与失败

- 单任务 `add/append/prepend/replace/pri` 通常返回 `{"ok":true,"action":"...","task":{...}}`。
- `depri N...` 对每项输出一个 JSON 对象，多项时是 JSON Lines，不能整段按单个对象解析。
- `done/del` 返回 `{"ok":true,"action":"...","tasks":[...]}`；`done` 的 JSON 不包含新生成的下一期，必须重新 list。
- `archive` 返回 `{"ok":true,"action":"archive","count":N}`，目标路径按 `DONE_FILE` 规则确认，不依赖文本输出猜测。
- 通常退出码 0 为命令结束，1 为操作错误，2 为参数错误；顶层 I/O 错误也可能失败。即使开 `--json`，stderr 仍可能是普通文本。批量命令可能部分成功、退出非零却同时输出 `ok:true`；删除正文清理失败时任务也可能已删除。先刷新数据、逐项核验，再报告；不直接重跑。

## 5. 多行正文增删改查（不是 CLI 子命令）

**查询**：从任务 `raw` 解析引号外的 `note:`，按正文根目录得到规范化路径，检查越界／符号链接后用文件读取工具读取。区分“没有链接”“链接文件不存在”“读取失败”，不能把后两者视为空正文。

**新增**：预览正文、唯一新文件路径和将附加的 `note:` 链接；二次确认后创建不覆盖既有文件的正文（权限限制为用户私有），再用 `append` 或 `replace` 将链接加入同一已确认任务。不要复用标题 slug 覆盖同名正文。两步不是事务；第二步失败时报告可能留下未关联文件，不能未经确认自行删除或重做。

**修改**：先检查待办和归档是否有多个任务共享同一规范化正文路径。共享文件修改会影响全部引用，预览必须列出这些任务；要仅改一个任务则提议复制到新唯一文件并更新该任务链接。读取并预览精确差异，确认后重新核验内容、链接和共享引用，备份并用文件工具精确修改，不拿标题行重建整份正文。

**删除**：区分“解除链接”“清空内容”和“删除文件”，先澄清意图。若保留任务但删除正文，预览链接变更与物理文件删除的各自效果；确认后先移除已确认的链接、重新核对待办／归档无其他引用，再删除已授权且有备份的文件。文件还被引用时不删除；中途发现数据变更停止并重新确认。不要借整条任务 `del` 达到只删正文的目的。

直接文件写入要求：用户退出相关 TUI／编辑器，或有可靠的协作锁和冲突检测；否则只提供方案，不覆盖并发编辑。正文目录的 `.lock` 是应用的协作锁，操作系统文件锁才生效，不能创建同名文件就当已加锁。新文件使用排他创建，更新前核对原内容并采用精确修改／安全原子替换；不要盲目覆盖符号链接。备份、临时文件、正文创建和失败后的修复范围都必须包含在已确认方案中。

不创建自动扫描／自动修复脚本；只有用户明确需要而宿主能安全执行以上步骤时才直接写正文，否则把已确认内容交给用户在 TUI 正文编辑器中保存。
